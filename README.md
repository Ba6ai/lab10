## Задание №1 LexicalAnalyzer


### Алгоритм решения

#### Лексический анализвтор - первый этап компилятора. Он проверяет правила паскаля (делает парсер)
#### Задача заключается в разбитии сплошного текста на токены и заменить их на числовые коды, с которыми ПК прощё работать.
#### 1) Сначала убирается мусор (пробелы и отступы) и проверяется текущий символ.
#### 2) Запоминаются координаты
#### 3) Конструкция switch-case с распознаванием чисел, букв, различных знаков.
#### 3.1.1) Распознавание чисел (0-9). В цикле while считываются цифры одна за другой. Каждая новая строка добавляется к результату формулой nmb_int = 10 * nmb_int + digit;
#### 3.1.2) Есть защита от переполнения. Integer ограничен 16 битами (32767 символов). Перед добавлением числа, if проверяет чтобы число не вышло за предел. Если вышло - то ошибка 203 и сброс значения до 0.
#### 3.2) Распознавание строчных и заглавных букв. Когда лексёр видит букву или знак подчёркивания, он в цикле собирает буквы и цифры в одну строку name.
#### 4) Двухуровневый поиск по таблице KeyTable.Kw - используется таблица для оптимизации. Таблица сгруппированная по длине строк, работает быстрее, тк компилятору не надо перебирать все ключеные слова Пасакаля.
#### 4.1) Берётся длинна слов len = name.Legth
#### 4.2) Ищется внутренний словарь именно для такой длинны (Kw.TryGetValue(len, out var subDictionary). Если слово длинной 3 (например "var"), то смотрит только в словарь KeyWords.cs
#### 4.3) Итог- если слово найдено в словаре, лексёр понимает что это ключевое слово и возвращает его личный код.
#### 5) Распознавание символов и составных знаков. Некоторые знаки состоят из одного символа (например ; или :), а некоторые из двух (например "<="). Лексёр заглядывает на один символ вперёд, если после идёт "=", то он возвращает код присванивания assign(51). Если нет - оставляет код двоеточия colon(5).
#### 6) Если встретит неизвестный символ, то пойдёт дальше и зафиксирует ошибку '0000'



## Задание №2 SyntaxisAnalyzer с нейтрализацией ошибок


### Алгоритм решения

#### Синтаксический анализатор - проверяет правила грамматики языка. Он следит, чтобы слова шли в строго определённом Паскале порядке, то есть имеет ли право оператор так писаться?. Парсер написан методом рекурсивного спуска. То есть для каждого грамматического правила (блок переменных, запись, составной оператор) в коде есть свой отдельный метод, который вызывает другие методы по цепочке.
#### 1) Метод Accept - сердце парсера. Он проверяет простую вещь: равен ли текущий токен от лексёра (_sym) тому, который должен быть по правилам Паскаля (expectedToken). Если совпали, то идёт дальше. Если нет, то парсер фиксирует синтаксическую ошибку и запускает нейтрализацию по Айронсу.
#### 2) Нейтрализация ошибок по методу Айронса - while (_sym != 0 && _sym != expectedToken && followers.Contains(_sym)). То есть если программист забыл поставить ";" компилятор не должен падать или зависать. По методу Айронса, парсер начинает пропускать следующие токены до тех пор, пока не встретит: ожидаемый токен ИЛИ токен из списка восстановлений followers - это ключевые слова (например begin или ident), парсер может гарантированно продолжить работу кода, не обращая внимания на предыдущий мусор.

#### Основные методы:
#### 1) Раздел описания переменных (VarBlock, VariableDeclaration)
#### 1.1) Метод VarBlock() ждёт ключевое слово var, а затем в цикле вызывает VariableDeclaration для каждой строчки объявлений
#### 1.2) VariableDeclaration умеет разбирать переменные через запятую, ищёт обязательное двоеточие, а затем вызывает определение типа TypeDeclaration.
#### 1.3) Метод TypeDeclaration парсит внутренности записи (поля) в цикл, пока не упрётся в обязательное закрывающее слово end.

#### 2) Разделение параметров (CompoundStatement, Statement)
#### 2.1) ComoundStatement - это блок begin ... end. Он запускает цикл while (_sym != LexicalAnalyzer.endsy), внутри которого по очереди вызывает обработку каждого оператора через метод Statement().
#### 2.2) Метод Statement работает как диспетчер. Он смотрит на текущий токен и решает, какой оператор пред ним: begin -> вызывает вложенный CompoundStatement().    with-> вызывает оператор присоединения AssigmentStatement().     Если имя переменной ident -> регистрируется ошибка 42, сдвигает лексёр на один шаг вперёд через NextSym, чтобы избежать бесконечного цикла и продолжить работу.

#### 3) Оператор присваивания и работа с полями записей (AssigmentStatement, Dessignator)
#### 3.1) По заданию надо уметь присваивать значения как простым, так и поля записей через точку (например: student.age := 20;)
#### 3.2) За это отвечает метод Dessignator. Он сначала считывает имя переменной, а затем в цикле while(_sym == LexicalAnalyzer.point) по цепочке съедает точки и следующие за ним имена полей (id.id.id...).
#### 3.3) После этого метод AssigmentStatement проверяет наличие знака := и разбирает правую часть через Expression().
#### Так же при 1 ошибке может выдать сразу 4-6 ошибок - это особенность нейтрализации по методу Айронса. Если пропущен ключевой токен пропущен, то парсер может проскочить начало следующего блока, из-за чего происходит каскадный эффект ошибок
