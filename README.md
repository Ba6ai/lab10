## Задание №1 LexicalAnalyzer


### Алгоритм решения

#### Лексический анализвтор - первый этап компилятора. Он разбивает сплошной исходный текст программы на лексемы и заменяет их числовыми кодами токенов.
#### 1) Сначала убирается мусор (пробелы и отступы) и проверяется текущий символ.
#### 2) Запоминаются координаты
#### 3) Конструкция switch-case с распознаванием чисел, букв, различных знаков.
#### 3.1.1) Распознавание чисел (0-9). В цикле while считываются цифры одна за другой. Каждая следующая цифра добавляется к текущему числу формулой `nmb_int = 10 * nmb_int + digit;`
#### 3.1.2) Есть защита от переполнения. Integer ограничен 16 битами. Перед добавлением цифры, if проверяет чтобы число не вышло за предел. Если вышло - то ошибка 203 и сброс значения до 0.
#### 3.2) Распознавание строчных и заглавных букв. Когда лексёр видит букву или знак подчёркивания, он в цикле собирает буквы и цифры в одну строку name.
#### 4) Двухуровневый поиск по таблице `KeyTable.Kw` - используется таблица для оптимизации. Таблица организована в виде словарей, сгруппированных по длине слова. Сначала определяется длина идентификатора, затем выполняется поиск только в соответствующем словаре. если слово найдено, возвращает код ключевого слова, иначе оно считается идентификатором.
#### 4.1) Берётся длинна слов len = name.Legth
#### 4.2) Ищется внутренний словарь именно для такой длинны `(Kw.TryGetValue(len, out var subDictionary)`. Если слово длинной 3 (например "var"), то смотрит только в словарь KeyWords.cs
#### 4.3) Итог- если слово найдено в словаре, лексёр понимает что это ключевое слово и возвращает его личный код.
#### 5) Распознавание символов и составных знаков. Некоторые знаки состоят из одного символа (например ; или :), а некоторые из двух (например "<="). Лексёр заглядывает на один символ вперёд. Например : и ; имеют разные коды: colon = 5, assign = 51.
#### 6) Если встретит неизвестный символ, лексёр пропустит его и вернёт код "0".



## Задание №2 SyntaxisAnalyzer с нейтрализацией ошибок


### Алгоритм решения

#### Синтаксический анализатор проверяет, соответствует ли последовательность токенов грамматике языка Паскаль. В работе используется метод рекурсивного спуска. Для каждой основной конструкции программы создан отдельный метод. Анализ начинается с метода `Parse()`, который запускает разбор программы.
#### Структура вызова методов синтаксического анализатора: 
```
Program
├── VarBlock
│   └── VariableDeclaration
│       └── TypeDeclaration
│           └── RecordType
│
└── CompoundStatement
    └── Statement
        ├── AssigmentStatement
        │   ├── Dessignator
        │   └── Expression
        │
        ├── WithStatement
        │   └── Statement
        │
        └── CompoundStatement
```

#### 1) Метод Accept() - основной метод проверки токенов. Он сравнивает текущий токен (_sym) с ожидаемым (expectedToken). Если токены совпадают, парсер переходит к следующему. Если нет - фиксируется синтаксическая ошибка и выполняется нейтрализация
#### 2) Нейтрализация ошибок - при обнаружении ошибки парсер пропускает токены до тех пор, пока не встретит ожидаемый токен или один из токенов восстановления followers. Это позволяет продолжить анализ программы после найденной ошибки.
#### Основные методы:
#### 1) Раздел описания переменных (VarBlock, VariableDeclaration)
#### 1.1) Метод VarBlock() ожидает ключевое слово var, а затем вызывает VariableDeclaration() для каждой группы объявлений.
#### 1.2) VariableDeclaration() разбирает переменные через запятую, проверяет двоеточие и передаёт разбор типа в TypeDeclaration().
#### 1.3) TypeDeclaration() определяет тип. Если встречается record, вызывается RecordType(), который разбирает поля записи до end. Если встречается ident, он принимается как простой тип.
#### 2) Составной оператор и обработка операторов (CompoundStatement, Statement)
#### 2.1) CompoundStatement() разбирает блок begin ... end и последовательно вызывает Statement() для каждого оператора.
#### 2.2) Метод Statement определяет тип текущего оператора. Если начало оператора не распознано, фиксируется ошибка и выполняется переход к следующему токену:
```
begin - составной оператор (CompoundStatemen)
with - оператор присоединения (WithStatement)
ident - оператор присваивания (AssigmentStatement)
```
#### 2.3) WithStatement() - разбирает оператор присоединения вида with student do statement.
```
with student do
begin
    id := 5;
end;
```
#### 3) Оператор присваивания и работа с полями записей (AssigmentStatement, Dessignator)
#### 3.1) По заданию необходимо уметь присваивать значения простым переменным и полям записей, например student.age := 20;
#### 3.2) Dessignator() считывает имя переменной, а затем обрабатывает обращения к полям через точку (id.id.id...).
#### 3.3) AssigmentStatement() проверяет наличие := и разбирает правую часть через Expression().
#### После одной синтаксической ошибки может появиться несколько дополнительных сообщений из-за каскадного эффекта ошибок.
